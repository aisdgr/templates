# DOCS Domain

文檔域 - 定義文檔生成和管理的規則。

---

## 概述

DOCS Domain 包含專門針對文檔生成的行為約束規則。這些規則處理文檔特定的關注點，如模板佔位符、章節邊界、結構完整性和文檔可追溯性。

**總規則數**: 37 條
- **Constraints (約束)**: 28 條
- **Policies (策略)**: 9 條

---

## 規則類別

### AR - Artifact Isolation (製品隔離)

| 規則 ID         | 類型 | 描述                                          |
| --------------- | ---- | --------------------------------------------- |
| DOCS-AR-C-001   | 約束 | AI *必須*僅在文檔模板中聲明的佔位符內生成內容 |
| DOCS-AR-C-002   | 約束 | AI 絕不能跨章節生成內容                       |
| DOCS-AR-C-003   | 約束 | AI 絕不能生成默認附錄                         |
| DOCS-AR-C-004   | 約束 | 生成的文檔製品*必須*在結構上有效              |

## 新增規則

在 2026-03-19 的架構重構中，DOCS Domain 新增了 3 條 LG (Logging & Report) 類別規則：

- **DOCS-LG-P-001**: 文檔執行日誌
- **DOCS-LG-P-002**: 日誌追溯 ID
- **DOCS-LG-P-003**: 理由說明

這些規則確保文檔生成過程具有與程式碼生成相同的日誌和追溯能力。

## 使用建議

### 與 CORE Domain 配合

DOCS Domain 規則應與 CORE Domain 規則一起使用，以獲得完整的文檔生成約束：

```yaml
# Application Ruleset 範例：API 文檔生成
includes:
  # CORE 規則（通用）
  - CORE-AR-*
  - CORE-BD-*
  - CORE-CN-*
  - CORE-TR-*

  # DOCS 規則（文檔特定）
  - DOCS-AR-*
  - DOCS-BD-*
  - DOCS-CN-*
  - DOCS-ST-*
  - DOCS-LG-*
  - DOCS-TI-*
  - DOCS-TR-*
```

### 文檔類型

DOCS Domain 規則適用於多種文檔類型：

- API 文檔（OpenAPI、Swagger）
- 設計文檔（架構設計、詳細設計）
- 需求文檔（功能需求、非功能需求）
- 技術文檔（部署文檔、運維手冊）
- 測試文檔（測試計劃、測試報告）

## 文檔模板

DOCS Domain 規則通常與文檔模板配合使用：

1. **模板定義**: 在模板中聲明佔位符
2. **內容生成**: AI 僅在佔位符內生成內容 (DOCS-AR-C-001)
3. **結構保留**: 保留章節層次結構 (DOCS-ST-C-021)
4. **可追溯性**: 嵌入追溯 ID (DOCS-TR-P-001, CORE-TR-P-002)
