## 問題摘要

根據 `Concept.md` 的核心架構設計，當前 `RULE.md` 的分類方式存在根本性概念錯誤。當前採用 **Domain Category** 分類，但 BRA 框架要求使用 **Behavior Category** 分類。

---

## 核心概念差異

### 錯誤方式（當前）：Domain Category
- 先設計 Rule
- 再看 Rule 可應用在哪個 Domain
- 分類依據：應用領域（CODE、DOCS、LANG、GOV）

### 正確方式（BRA 要求）：Behavior Category
- 先定義 AI 決策行為類別
- 再從該決策行為類別衍生對應規則
- 分類依據：AI Decision Behavior（如 Code Generation、Test Generation 等）

---

## 違反 Concept.md 的關鍵原則

### 1. 分類邏輯錯誤

**當前問題**:
```
CODE Domain
├── AR - Artifact Isolation
├── BD - Boundary & Stop
├── CN - Constraint Neutrality
├── LG - Logging & Report
├── ST - Structural Change
├── TI - Test Integrity
└── TR - Traceability
```

**問題分析**:
- AR、BD、CN、LG、ST、TI、TR 不是 Behavior Category
- 這些看起來像是 Rule 的「特性」或「關注點」，而非 AI Decision Behavior
- 違反 Concept.md 第 647 行：*Behavior Category 先界定 AI 決策行為類別，再從這個決策行為類別設定規則*

**正確的 Behavior Category 範例**（來自 Concept.md 第 247-252 行）:
- Code Generation Behavior
- Test Generation Behavior
- Specification Generation Behavior
- File Modification Behavior

---

### 2. Rule 與 Category 的關係錯誤

**Concept.md 第 654 行明確規定**:
> 一條 Rule 只可以屬於一個 Behavior Category，也就是說 Rule 和 Category Ruleset 是一對多。

**當前問題**:
- LANG Domain 下的語言規則（GO、JAVA、JS、PY、RS、TS）應該屬於「Code Generation Behavior」
- 但它們被分類在 LANG Domain，而非依據決策行為分類
- GOV Domain 的規則可能涉及多種決策行為（Code Generation、Execution 等）

---

### 3. 子分類（AR、BD、CN 等）的角色混淆

**問題分析**:
- AR、BD、CN、LG、ST、TI、TR 看起來像是 Rule Metadata 的「關注點」或「標籤」
- 它們不應該是 Category，而應該是 Rule 的分類維度
- 一條 Rule 可能同時涉及多個關注點（例如：同時涉及 Traceability + Logging）

**建議處理方式**:
- 這些應該作為 Rule Metadata 的 `focus_area` 或 `category_tags` 欄位
- 不應該作為頂層的 Behavior Category

### 修正 3: 重新設計 Rule Metadata 結構

**當前問題**: AR、BD、CN、LG、ST、TI、TR 作為子分類，但實際上應為 Rule Metadata 的標籤

**建議的 Rule Metadata 結構**:

```yaml
Rule:
  id: CODE-AR-C-01
  behavior_category: Code Generation Behavior  # 新增：Behavior Category
  type: Constraint
  description: Must not create undeclared artifact types

  metadata:
    focus_areas:           # 新增：關注點標籤（原 AR、BD 等）
      - Artifact Isolation
      - Code Structure
    domain_tags:           # 新增：應用領域標籤
      - Code
    language_specific: false
    severity: major
    risk: medium

  # 原有的 metadata 欄位
  version: 1.0.0
  status: active
  owner: AISDGR
```

---

### 修正 5: Rule ID 編碼規則調整

**當前 Rule ID 格式**: `{DOMAIN}-{SUBCATEGORY}-{TYPE}-{NUMBER}`
- 範例: `CODE-AR-C-01`

**建議的新 Rule ID 格式**: `{BEHAVIOR}-{NUMBER}`
- 範例: `CG-001`（Code Generation Rule 001）
- 或: `CODEGEN-001`

**理由**:
- Behavior Category 是分類的核心
- Rule ID 應直接反映其所屬的 Behavior Category
- AR、BD、CN 等應為 metadata 標籤，而非 ID 的組成部分

**選項**:
- A. 粗粒度: Code Generation、Test Generation、Documentation Generation
